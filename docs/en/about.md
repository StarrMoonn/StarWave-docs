# What is StarWave?

StarWave is a differentiable wave-propagation toolkit for PyTorch that connects subsurface models, simulated observations, and model updates. Native CPU/CUDA paths and explicit PyTorch backends handle supported propagation, while autograd carries loss gradients back to the model, bringing forward modeling and inversion into a familiar tensor-and-optimizer workflow.

Read or download the [original 30-slide presentation](presentation.md) for an overview of FWI, automatic differentiation, and the StarWave workflow.

## What it provides

- **Wave simulation**: 2D/3D scalar acoustics, 1D/2D/3D acoustic Born, 2D VRZ, 2D/3D acoustic VTI and elasticity, and 2D GSLS viscoacoustics. The separate VRR extension adds 2D vector reflectivity. Each has its own model, source, recording and boundary conventions.
- **Gradients and FWI**: connect simulated records to a PyTorch loss, compute first-order model gradients, and update models in your own optimization loop.
- **Neural model representations**: pass a complete model generated by a user-defined network to the propagator and explore implicit neural representations (INRs) with wave physics.

Native scalar, VRZ and VTI use CUDA float32; their explicit Torch paths support CPU/CUDA with equation-specific limits. Both 2D and 3D scalar support first-order velocity gradients; only 3D scalar supports first-order source-waveform gradients, while 2D sources remain fixed. Acquisition locations are not differentiable. Other propagators have their own input-gradient contracts. See [Usage](usage.md) for types, shapes, units, and constraints.

This manual targets published V17 source (`0.1.0.dev17`), including [Born](usage.md#born-function), equation-specific flat-top boundaries and import-time native preparation. **PyPI 8.0.0 is not published; the available 7.1.0 wheel remains V16.** Born uses velocity perturbation δv and returns background/scattered states and records; its background operator differs from `starwave.scalar`. See [installation](installation.md) for matching source/build requirements.

## Origins and development

StarWave adapts CUDA propagation kernels from MIT-licensed [SWEEP](https://github.com/DeepWave-KAUST/sweep) and retains upstream attribution and license notices. Its development builds on that foundation with a unified PyTorch interface, model-gradient handling, input checks, and inversion workflows.

StarWave's call style takes cues from [Deepwave](https://github.com/ar4/deepwave), and selected time-resampling utilities are adapted from Deepwave. The elastic and Born implementations derive from Deepwave 0.0.27 with their own documented adaptations and preserved attribution. Its validation work also uses Deepwave reference code, with applicable MIT notices retained. [Deepwave's Usage documentation](https://ausargeo.com/deepwave/usage) inspired this manual's organization. StarWave's supported equations, parameter conventions, and return values are defined in this manual.
